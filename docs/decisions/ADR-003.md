# ADR-003: Task worktrees and plan integration

Status: accepted for foundation, 2026-09-05.

## Context

Tasks need independent edits and reliable dependency code.

## Decision

One branch/tree per task attempt; one integration tree; serialized integration and candidate re-review after base change.

## Alternatives

Shared checkout creates races; stacked task PRs add unnecessary first-release complexity.

## Consequences

More review cost for rebased parallel candidates; stricter reproducibility.

## Reversibility

Alternative delivery strategies can reuse task/candidate contracts.
