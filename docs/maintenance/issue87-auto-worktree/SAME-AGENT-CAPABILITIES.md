An unrelated child executor cannot substitute for the same agent.

## Conditional Claude automatic route

This is supported **instruction-driven orchestration**, not a hook directly switching its parent. A synchronous source-prewrite hook cancels the pending edit and returns a concise native-entry instruction to the same model. Standing main-session workflow/skill instructions direct that same agent to call its own `EnterWorktree` creation operation next, verify real binding, then freshly read and reconstruct the edit. Claude's documented denial reason is model-visible and supports additional context. No user instruction is needed between these steps when the operation and policy allow it. The model must actually make the native call; a notice or state marker cannot stand in for movement. [CITED: https://code.claude.com/docs/en/hooks#pretooluse-decision-control]

Native creation is documented as not prompting; the mandatory outside-directory prompt applies to the existing-path form. WorktreeCreate can replace native creation and return a custom-root checkout that the host uses as the isolated session directory. This supports the trusted existing repository location hook as the creation provider. It does not authorize bypassing existing-path approval by rewriting an edit. Native hook path screening and existing-name reuse still need integration coverage; the documented no-prompt rule is not a promise that every account policy, hook trust failure or filesystem error succeeds unattended. [CITED: https://code.claude.com/docs/en/tools-reference] [CITED: https://code.claude.com/docs/en/hooks#worktreecreate]

Gate the route positively before treating it as supported:

- The actual native tool pool and schema must expose creation-form `EnterWorktree` to this same agent. If the host advertises a name argument, use that advertised field; do not invent an unobserved invocation schema or a minimum CLI release. A Claude installation label alone is insufficient.
- The agent must be eligible for creation, outside a worktree and without a pinned-role restriction that permits only the path form. An already correctly isolated agent needs no movement. Wrong-root/pinned exceptions are separate unsupported cases, not permission to create a replacement child.
- Agent definitions must permit the tool. The inspected coder role's restrictive tool list omits native entry and would need a bounded export change if that role is an eligible caller. Main-session skills' `allowed-tools` grants are preapproval, not a tool availability restriction; omitting the tool there does not itself remove it. A skill using `context: fork` moves a child rather than its caller and is unsuitable for this main-session route.
