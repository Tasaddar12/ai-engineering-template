## Binding, hooks and dirty data

Claude documents that native entry moves the session's working directory, write access and project configuration. Hook JSON cwd follows the worktree, while the original project-directory hook variable stays anchored. Creation is a fresh checkout with tracked files; ignored files require explicit inclusion, or copying inside a custom creation hook. Neither this evidence nor the installed repository hook proves migration of a dirty primary index and worktree. Preserve them and verify any required transfer explicitly. [CITED: https://code.claude.com/docs/en/worktrees#ask-claude-to-create-a-worktree] [CITED: https://code.claude.com/docs/en/worktrees#copy-gitignored-files-into-worktrees]

Codex desktop documents Handoff as moving chat and code. Managed creation can apply local changes when that starting option is selected; ignored files need explicit inclusion. That is a different contract from this environment's creation tool, which explicitly does not copy uncommitted changes. Exact staged/untracked/ignored preservation and conflict behavior still need live acceptance evidence for the chosen transition. [CITED: https://learn.chatgpt.com/docs/environments/git-worktrees#how-codex-manages-worktrees-for-you]

Preservation acceptance follows the chosen native transfer: every initial change must remain accounted for and recoverable at its documented resulting location. A legitimate host move may relocate dirty state; requiring the primary checkout's bytes and index to stay identical would be an additional restriction the latest user clarification did not impose.

Neither host's documented pretool response includes invoking another native tool or atomically moving the running session and replaying the pending edit. Input replacement preserves the pending tool's identity; cancellation prevents that tool. Claude WorktreeCreate runs when native entry/creation already occurs and supplies the checkout path; shell creation does not trigger it. Therefore a pretool hook can request the next native transition, but the hook alone cannot claim it occurred. This is the documented-contract boundary, not proof about private APIs. [CITED: https://learn.chatgpt.com/docs/hooks#pretooluse] [CITED: https://code.claude.com/docs/en/hooks#pretooluse-decision-control] [CITED: https://code.claude.com/docs/en/hooks#worktreecreate]

No cited contract promises automatic replay of an interrupted edit after movement. The safe proposed sequence is: prevent the old-root mutation; perform the supported native same-session transition; confirm actual binding; read the destination afresh; reconstruct and execute the intended edit there. Allowing the original pending absolute path after a cwd change can still mutate the old checkout. A child process changing directory does not rebind its parent. An unrelated child executor cannot substitute for the same agent.

## Required live acceptance evidence

These are proposed acceptance checks, not tests performed:

1. Record the real host/version, session/thread identity, active agent identity where available, original cwd, repository/branch/base and primary index/worktree fingerprints. Confirm the transition tool is actually callable in that agent's role.
2. Trigger one source edit from the primary checkout. Prove the pending edit has not run before movement. Preserve task-note/read-only behavior and PR 86's warning preference.
3. Invoke native movement for that same target session. Capture completion and stable identity; a new child/fork, intended-root marker or attached checkout is insufficient. Honor required host approval; never bypass it through a rewritten path.
4. From subsequent tools without per-command cwd overrides, verify the real cwd, Git root/branch/base and a relative file read in the worktree. Verify destination write permission and loaded repository context. Include a later turn so persistence is observed.
5. Re-read destination content, rebuild the original intended mutation and execute it once. Prove that resumed edit landed only in the target checkout; no old-root absolute path or still-running terminal continues writing there. Account separately for any documented native relocation of pre-existing dirty data.
6. Exercise a dirty primary, existing destination, denied movement, timeout/uncertain completion and offline case. Prove staged/unstaged/untracked/ignored data remain preserved, identity is not duplicated and retries cannot create multiple worktrees or apply the edit twice. Never auto-stash, reset, clean or remove dirty work.

## Recommendation and remaining blocker

Do not release production code against preparation-only RED tests as fulfillment of the clarified request. Keep the six existing drafts frozen and PR 97 unmerged. Choose a real supported host integration first: native Claude entry where available; Codex host Handoff for the same target chat; or a deliberately implemented external client transition on the same thread after stopping the active turn. In the selected environment, self-transition is unavailable through the observed tool contracts. A separately authorized coordinator moving the same target is a possible product-supported route, but availability, target identity, host interruption/resumption and completion must be demonstrated before implementation claims success. An instruction telling the agent to move later is still only an instruction. No substitute meets the current acceptance, and this research grants no new installation, host modification or provider-write authority.

Unknowns blocking fulfillment: exact installed release and tool availability in the intended runtime; native same-agent continuation after cancellation; dirty-data transfer semantics; and proof that all subsequent relevant tools use the destination.
