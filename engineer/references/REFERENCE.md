# Shared method reference catalog

This directory preserves the complete reusable methods imported from upstream and their project-specific reconciliation. Read only the method sections required by a named question; read complete templates when authoring their artifacts.

Methods add no commands, authority or scope. The consuming command/workflow owns procedure; the assigned role owns its output; the Python runtime owns structured planning mutations. The coordinator owns worker lifecycle, integration, shared records and publication. Scouts provide cited read-only evidence and never dispatch children.

Do not install tools, create infrastructure or change host settings because a method mentions a capability. Use available project tooling, record missing capabilities and preserve incomplete evidence. Honor the actual instruction hierarchy and explicit user authorization.

| Question | Method families |
|----------|-----------------|
| Locate source / investigate behavior | scout-codebase, questioning, research-philosophy |
| Plan outcome and dependencies | planner-guidance, planner-preconditions, planner-coupling, planner-revision |
| Diagnose an observed failure | debugger-philosophy, debugger-techniques, debugger-bug-taxonomy, debugger-fix-acceptance |
| Verify observable behavior | honest-verifier, verification-patterns, verifier-phase-gates, verification-evidence |
| Review a particular stack | relevant stack section in verification-patterns; current source and primary project documentation |
| Preserve authority and handoffs | checkpoints, worker-handoff, worktree-sessions, git-workflow |

Examples are discovery aids, not proof. Preserve full algorithms, tables and examples; adapt actual runtime interfaces instead of replacing methods with summaries.
