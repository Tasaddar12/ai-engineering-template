# Completion, delivery, and archive

Task acceptance requires passing implementation and consistency reviews for the same candidate plus verified validation evidence. It does not by itself complete a plan.

Integrate accepted task candidates in dependency order, resolve conflicts through owned repair work, and run plan-wide validation. A fresh plan integration review must bind the combined candidate. Prepare remote delivery locally first; publish, merge, deploy, or delete remotely only with current authority and policy support. Observe the actual remote head, checks, reviews, and merge result rather than inferring them from a request.

The current manual kit supports one bounded lifecycle move: after the exact task candidate has both required passing reviews and accepted evidence, the coordinator may change that task's `status` to `completed`, keep `archived: false`, move the record from `tasks/current/` to `tasks/completed/`, and keep its other fields, plan membership, and graph node unchanged. Update affected nonstructural narrative links in the same local change; for example, the generated `plan.md` links to `tasks/current/TASK-001.json` and must point to `tasks/completed/TASK-001.json` when that task moves. Inspect incoming links and explicitly check the updated targets because the installed validator does not scan every project-authored Markdown file. Run the record validator and confirm the structural digest is unchanged: it excludes lifecycle status and the physical task bucket. If the move requires changing a structural reference, the digest changes, a link is unresolved, or validation fails, restore the prior record, location, and narrative links and return the change for replanning. Never represent a partial move as committed.

Whole-plan completion, plan archival, and task archival remain reserved. Current physical plan paths occur in structural references, so moving or rewriting them can invalidate the approved digest. A future lifecycle service must use plan-qualified logical references and update location, status, `.codex/STATE.json`, manifests, and retained approval provenance transactionally. Until that contract is implemented and tested, preserve plan history inside the current plan bundle and do not move a plan or task into an archived bucket.

Before removing a linked worktree, verify its registered path and branch, clean tracked/untracked state, no live lease or process, observed integration, and retained failed/unmerged commits. Use Git removal without force, then remove the empty `.worktrees/` container.
