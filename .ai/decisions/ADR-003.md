# ADR-003: Repository-local task worktrees and plan integration

Status: accepted for foundation, 2026-09-05.

## Context

Tasks need independent edits and reliable dependency code.

## Decision

One branch/tree per task attempt and one integration tree, all created beneath the repository base in `.worktrees/`; serialized integration and candidate re-review after base change. Remove clean merged worktrees through Git and remove the empty `.worktrees/` container. Retain failed or unmerged work through branches and commits rather than permanent duplicate checkouts.

## Alternatives

Shared checkout creates races; stacked task PRs add unnecessary first-release complexity.

## Consequences

More review cost for rebased parallel candidates; stricter reproducibility.

## Reversibility

Alternative delivery strategies can reuse task/candidate contracts.
