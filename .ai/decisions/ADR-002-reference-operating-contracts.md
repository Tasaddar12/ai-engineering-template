# Reference operating contracts

## Context

The user supplied a reconstruction of another project's AI Orchestration
Template and explicitly asked to make this work close to it. The existing
scaffold already supplied the desired directories but used shorter role
definitions, duplicate lifecycle metadata and less concrete repair proof.

## Decision

The proposed adaptation adopted tiered permissions, a contradiction route,
current-only specs, exact plan contract wording, directory-owned stages,
regression proof, positive role scopes and wave/track procedures.

It retained the user's .ai paths, state/PROJECT.md, requested roles and
report-summary-decision requirement. Explicit execution authority covers
ordinary in-scope reconciliation; it does not grant new intent or delivery.

## Alternatives

| Alternative | Reason accepted or rejected |
| --- | --- |
| Keep the original small draft | Leaves requested reference behavior absent. |
| Copy the reconstruction verbatim | Conflicts with the user's chosen paths. |
| Adapt its operating principles here | Keeps the requested structure and rules. |

## Consequences

The document contracts became more explicit without installing a runtime.
Plan-checker and scribe supplied focused proposal/documentation boundaries.
Optional runtime mappings and automatic enforcement stayed outside the draft.
Affected current behavior is owned by SPEC-001.

## Supersession and revisit

This proposal complements ADR-001 rather than replacing its rationale.
Revisit if the user requests actual dispatch or a different authority model.
