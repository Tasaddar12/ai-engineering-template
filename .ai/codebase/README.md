# Codebase maps

Create maps only for areas about to be researched or changed. Useful subjects
include structure, integration boundaries, conventions and testing.

Name the inspected revision, relevant entry points, callers, test commands and
known limits. Link source areas rather than copying files. Refresh a map when
changes invalidate it; timestamps alone do not establish freshness.

Maps describe the existing system. Phase research investigates a particular
change. Neither source overrides phase decisions or proves current behavior
without inspection.
