# Installer inputs

These files are packaging inputs for [install.py](../install.py). The installer
does not copy this directory into adopting projects.

- `agent-entry.txt` is installed as a delimited block in root AGENTS.md for Codex
  or CLAUDE.md for Claude, with references rewritten to that host's layout. It is
  project guidance; the source repository's root AGENTS.md remains maintainer guidance.
- PROJECT, REQUIREMENTS, ROADMAP and STATE text files become pending onboarding
  records only when destination records are missing. Complete authoring methods
  and illustrative examples remain in the selected host's `templates` directory.
- `codex-agents/*.toml` supplies one native Codex definition per complete role.
  The installer copies these beside the installed `.codex/agents/*.md` methods
  and rewrites the direct role-file instructions. Claude does not receive TOML
  definitions; Claude worker models resolve from `.planning/config.yaml` and
  are passed inline at dispatch. Only `luna_scout` carries `model: haiku` in
  Markdown frontmatter, with no effort.
  Codex model and effort resolution uses the native agent TOML definitions.
  An existing destination config is preserved for every profile. Native hook
  registrations are generated by the installer;
  personal host directories are never packaging inputs.

Commands and agents keep their names under `.codex` or `.claude`. Full skill
bodies are installed directly in `.agents/skills` for Codex and `.claude/skills`
for Claude. There are no generated skill wrappers or renamed command/agent folders.
There is no separate `.ai` directory in a fresh installed project. Upstream download URLs continue to
identify the source packaging script.

Changes to these inputs require testing the rendered destination, including
project context, preservation, links and runtime startup.

The `codex-agents/*.toml` files keep native `model` and `model_reasoning_effort`
fields: those are Codex's own agent configuration surface, separate from the Markdown definitions. The
Markdown worker agents carry no `model:` frontmatter — their Claude model is
injected inline at dispatch, resolved from `.planning/config.yaml`.

The runtime fixes `luna_scout` to Claude `haiku` with omitted effort or Codex
`gpt-6-luna` with `high` effort, regardless of project YAML overrides. Its Claude
Markdown frontmatter is the sole `model:` exception.
