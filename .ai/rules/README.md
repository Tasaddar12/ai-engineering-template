# Modular project rules

Keep focused, reusable project constraints in this directory. Shared RULES.md
still owns workflow authority; skills explain methods, while these files state
project conventions that apply across assignments. Installation places this
folder under the selected host root alongside its agents and templates.

Start with [the rule template](../templates/rule.md). Copy it to a descriptive
file here only when an actual project convention is established; do not fill
this reusable template with an invented adopting project's rules.

For each rule, state its scope, exact requirements, rationale, examples and
verification. Keep one topic per file. Link to existing specifications rather
than duplicating their requirements. Maintain the catalog below as rules are added.

| Rule | Applies when | Owner/source |
|---|---|---|
| No project rules yet | Onboarding has not established project conventions | Project owner |

Agents read this catalog and load applicable files before planning, implementation,
debugging and review. The coordinator includes relevant rule paths in assignments.
Missing referenced rules are a documentation gap; conflicting rules go to the
coordinator for reconciliation with actual user intent. Do not silently choose
one or treat a rule as permission to expand scope.
