# Report a problem or request

Input: a user report, bug, drift observation or proposed change.

1. Read the current fact owners and inspect relevant evidence read-only.
2. Allocate an intake ID and fill templates/intake.md under plans/intake.
3. Separate observed facts, expected outcome and unknowns. Link related records.
4. Return templates/decision-summary.md with one bounded proposed next action.
5. Wait for yes, no or requested changes under RULES. Record the decision in the journal.

Output: a linked intake report and user-facing decision summary. Reporting itself
never schedules implementation or installs tooling.
