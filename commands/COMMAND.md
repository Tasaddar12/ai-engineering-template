# Engineer command catalog

Read the complete selected method before using it. This is an authoring catalog; run the pinned installer to register the host assets.

A command selects the complete workflow it names. Discussion and planning do not grant implementation or merge authority.

| Method | Purpose |
|---|---|
| [add-tests](add-tests.md) | Generate tests for a completed phase based on UAT criteria and implementation |
| [audit-fix](audit-fix.md) | Autonomous audit-to-fix pipeline — find issues, classify, fix, test, commit |
| [audit-milestone](audit-milestone.md) | Audit milestone completion against original intent before archiving |
| [audit-uat](audit-uat.md) | Cross-phase audit of all outstanding UAT and verification items |
| [capture](capture.md) | Capture ideas, tasks, notes, and seeds to their destination |
| [cleanup](cleanup.md) | Archive accumulated phase directories from completed milestones |
| [code-review](code-review.md) | Review source files changed during a phase for bugs, security issues, and code quality problems |
| [complete-milestone](complete-milestone.md) | Archive completed milestone and prepare for next version |
| [debug](debug.md) | Systematic debugging with persistent state across context resets |
| [discuss-phase](discuss-phase.md) | Gather phase context through adaptive questioning before planning. |
| [docs-update](docs-update.md) | Generate or update project documentation verified against the codebase |
| [execute-phase](execute-phase.md) | SDD phase execution — execute all plans in a phase with dependency-aware wave parallelization |
| [explore](explore.md) | Socratic ideation and idea routing — think through ideas before committing to plans |
| [extract-learnings](extract-learnings.md) | Extract decisions, lessons, patterns, and surprises from completed phase artifacts |
| [fast](fast.md) | Execute a trivial task inline — no subagents, no planning overhead |
| [forensics](forensics.md) | Post-mortem investigation for failed Engineer workflows — diagnoses what went wrong. |
| [health](health.md) | Diagnose planning directory health and optionally repair issues |
| [inbox](inbox.md) | Triage and review open GitHub issues and PRs against project templates and contribution guidelines. |
| [manager](manager.md) | Interactive command center for managing multiple phases from one terminal |
| [map-codebase](map-codebase.md) | Analyze codebase with parallel mapper agents to produce .planning/codebase/ documents |
| [milestone-summary](milestone-summary.md) | Generate a comprehensive project summary from milestone artifacts for team onboarding and review |
| [new-milestone](new-milestone.md) | Start a new milestone cycle — update PROJECT.md and route to requirements |
| [new-project](new-project.md) | Initialize a new project with deep context gathering and PROJECT.md |
| [next](next.md) | Smart entry — detect project state and route to the right next Engineer action. |
| [onboard](onboard.md) | Guide existing codebase onboarding through mapping and planning setup |
| [pause-work](pause-work.md) | Create context handoff when pausing work mid-phase |
| [phase](phase.md) | Multi-phase management — add, insert, remove, or edit phases in ROADMAP.md (roadmap phase CRUD) |
| [plan-phase](plan-phase.md) | Create detailed phase plan (PLAN.md) with verification loop |
| [progress](progress.md) | Check progress, advance workflow, or dispatch freeform intent — the unified Engineer situational command |
| [quick-batch](quick-batch.md) | Batch several `/quick`-shaped tasks together — planned, dispatched, and merged as one run |
| [quick](quick.md) | Execute a quick task with Engineer guarantees (atomic commits, state tracking) but skip optional agents |
| [resume-work](resume-work.md) | Resume work from previous session with full context restoration |
| [review-backlog](review-backlog.md) | Review and promote backlog items to active milestone |
| [secure-phase](secure-phase.md) | Retroactively verify threat mitigations for a completed phase |
| [ship](ship.md) | Create PR, run review, and prepare for merge after verification passes |
| [spec-phase](spec-phase.md) | Clarify WHAT a phase delivers with ambiguity scoring; produces a SPEC.md before discuss-phase. |
| [thread](thread.md) | Manage persistent context threads for cross-session work |
| [ui-phase](ui-phase.md) | Generate UI design contract (UI-SPEC.md) for frontend phases |
| [ui-review](ui-review.md) | Retroactive 6-pillar visual audit of implemented frontend code |
| [update](update.md) | Update Engineer from a selected pinned source revision |
| [validate-phase](validate-phase.md) | Retroactively audit and fill Nyquist validation gaps for a completed phase |
| [verify-work](verify-work.md) | Validate built features through conversational UAT |
